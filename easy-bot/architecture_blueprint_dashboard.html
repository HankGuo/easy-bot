七层工业级开源组件选型与选型理由清单 (Component Selection & Rationale)

每一层均选用 GitHub 上最成熟、维护最好、协议最宽松的商用积木

全链路 TypeScript 同构
L1
宿主与表现层 (Desktop Host & UI Shell)
负责：跨平台窗口、Ant Design 浅色工作台、代码 Diff、Markdown 流式渲染、xterm.js 终端模拟
MIT 许可 TypeScript + React
选定开源组件
Electron 32 + Ant Design 5.0 + Tailwind
github.com/electron/electron
选型理由（为什么选它）：
• 成熟度天花板：全球经过 VS Code、Slack 检验，对 macOS 视网膜屏、Windows 高 DPI、系统原生托盘、多窗口管理支持最完美。
• 对标 WorkBuddy / Codex：采用 Ant Design 浅色工业设计语言，彻底摒弃黑客暗黑风，符合企业严肃办公审美。
L2
桥接与网关协议层 (Protocol Gateway & IPC)
负责：UI 与后台核心解耦通信、高危操作人工弹窗确认 (Approval Gate)、流式事件转发
Apache 2.0 标准 ACP 规范
选定开源组件
@agentclientprotocol/sdk + WebSocket
github.com/agentclientprotocol
选型理由（为什么选它）：
• 拒绝私有私造协议：ACP 是专门为智能体与客户端通信制定的行业标准，比手工手写 193 个 IPC 管道干净解耦 10 倍。
• 原生支持人机协同审批（Human-in-the-loop）：当模型要删除文件或执行高危命令时，ACP 协议天然具备“挂起拦截与用户点击确认”机制。
L3
智能体循环核心 (Agent Loop & State Machine)
负责：感知-思考-动作(Observe-Plan-Act)状态机、Cordis 插件化生命周期、流式 Tool-Call 调度与上下文压缩
MIT 官方许可 DeepSeek 官方核心
选定工业级开源组件
DeepSeek Harness (@deepseek-ai/dsh)
github.com/deepseek-ai/deepseek-harness
选型理由（为什么选它）：
• 顶流生态背书与完全合规：DeepSeek 官方开源的 Agent 运行时，基于 MIT 协议，彻底摆脱自研脆弱循环和历史代码纠纷。
• Cordis 时空插件化架构：将高校导师角色矩阵、学术 RAG、受限代码沙箱以标准插件解耦挂载，扩展性达企业级标准。
• 工业级鲁棒性与异常自愈：针对大模型流式打字、思维链 (Thinking Process) 与复杂 Tool-Call 自带步进生命周期控制，杜绝死循环。
L4
多模型抽象与网关路由层 (Universal LLM Gateway)
负责：统一抹平各家大模型接口、流式 SSE 解析、Tool-Call 工具调用格式互转、Token 财务台账
Apache 2.0 全模型兼容
选定开源组件
Vercel AI SDK (@ai-sdk/openai)
github.com/vercel/ai
选型理由（为什么选它）：
• 全行业通用标准：支持 OpenAI 格式、Anthropic 格式、以及局域网内的 vLLM / Ollama 私有部署模型。
• 流式打字机响应最稳：内置完善的流式重试机制与 Tool Calling 格式归一化，企业换模型只需改一行配置。
L5
生态协议与知识检索层 (MCP & Hybrid RAG)
负责：官方 MCP 工具生态接入、文件操作工具集、企业知识库 BM25+向量 RRF 双路混合召回
MIT / Apache 2.0 官方生态标准
选定开源组件
@modelcontextprotocol/sdk + WeKnora 规范
github.com/modelcontextprotocol
选型理由（为什么选它）：
• MCP 是当前事实标准：全球上万个现成工具（查 SQL、调 GitHub、搜文档）即插即用，彻底解决工具扩展问题。
• RAG 采用腾讯 WeKnora 规范：采用词法 BM25 + 语义向量 RRF 双路融合打分，避免单一向量数据库把专有名词搜错的通病。
L6
视觉感知与电脑操作层 (Computer Use & Vision)
负责：屏幕截取感知、控件图标视觉识别 (Grounding)、原生键鼠模拟驱动、一键急停安全熔断
MIT / Apache 2.0 纯视觉+原生驱动
选定开源组件
Anthropic Computer-Use + OmniParser + Nut.js
github.com/nut-tree/nut.js
选型理由（为什么选它）：
• 微软 OmniParser 控件定位：直接把屏幕截图解析为按钮坐标 `[x,y]`，不需要申请 macOS 敏感的 Accessibility 辅助功能树，准确率极高。
• Nut.js 原生驱动：全平台原生模拟鼠标移动、拖拽和键盘录入，代码纯净。
• 外置一键急停浮窗（Emergency Stop）：只要用户移动鼠标或按 Esc，系统强制熔断，防止失控。
L7
执行隔离沙箱与安全层 (Dual-Mode Execution Sandbox)
负责：命令隔离执行、路径白名单强校验、高危黑名单拦截 (rm -rf / 提权阻断)、不可篡改审计日志
100% 真实安全 双模按需切换
选定开源组件
Micro-Sandbox 内核 + Docker Engine SDK
对标腾讯 CubeSandbox 规范
选型理由（为什么选它）：
• 双模式兼顾体验与合规：默认模式采用 Micro-Sandbox（基于操作系统原生受限进程与白名单绝对路径校验），0 毫秒冷启动、无需客户安装任何 Docker，绝不穿透系统目录；重度构建支持一键接入 Docker。
• 绝不妥协关沙箱：所有写操作被严格圈定在指定工作区，指令与执行结果落盘防篡改审计日志。

技术决策立项总结：

整套方案全部基于全网验证通过的顶流开源标准（MIT / Apache 2.0）构建，核心技术栈保持纯 TypeScript 同构。我们无需手搓轮子，只需按照上述 7 层进行工业级加固、协议标准化组装和企业局域网闭环对接。两周内即可完成企业级商用版本的工程交付，彻底实现代码自主可控、零公网依赖、物理隔离私有化。
